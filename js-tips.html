optional-chaining.js Modern SyntaxBeginner 
const user = { profile: { name: 'Ada' } };

// Old way — one missing link and it throws
// const city = user.profile.address.city;   // 💥 TypeError

// Optional chaining short-circuits to undefined instead
const city = user.profile?.address?.city;    // undefined

// ?? only falls back on null/undefined — 0 and '' survive
const display = city ?? 'Unknown city';

// Works on methods and array indexes too
user.sendEmail?.();     // no-op if the method doesn't exist
const first = user.friends?.[0];

Optional chaining + nullish coalescing

Why pros use it: This pair kills the single most common JavaScript crash: Cannot read properties of undefined. The subtlety pros know: ?? only falls back on null/undefined, while || also discards perfectly valid values like 0, false and '' — a classic source of silent bugs in forms and settings.

// In function signatures: a self-documenting API

  return `${name} (${role})`;
}

// Array destructuring: swap without a temp variable

Destructuring with defaults and renaming

Why pros use it: Destructured function signatures are self-documenting — callers see exactly which fields matter, arguments become order-independent, and defaults live next to the names they belong to. spread-rest.js Modern SyntaxBeginner 
const base = { theme: 'dark', lang: 'en' };

// Immutable update — a NEW object, original untouched
const updated = { ...base, lang: 'fr' };

// Merge and clone arrays without mutation
const merged = [...listA, ...listB];

// Rest: collect "everything else"
const { theme, ...withoutTheme } = updated;

// Variadic functions without the arguments object
function sum(...numbers) {
  return numbers.reduce((total, n) => total + n, 0);
}

Spread and rest: immutable updates

Why pros use it: React, Redux and most state libraries detect changes by comparing object references — mutating an object in place makes changes invisible to them. Spread creates a new object cheaply, which is why { ...state, key: value } is the backbone of modern state management. Note it is a shallow copy: nested objects are still shared.

guard-clauses.js Modern SyntaxBeginner 
// ❌ Nested: the happy path is buried three levels deep
function shipOrder(order) {
  if (order) {
    if (order.paid) {
      if (order.items.length > 0) {
        // ship it
      }
    }
  }
}

// ✅ Guard clauses: fail fast, then read flat
function shipOrderClean(order) {
  if (!order) return;
  if (!order.paid) return;
  if (order.items.length === 0) return;

  // ship it — zero indentation, zero mental stack
}

Guard clauses over nested ifs

Why pros use it: Every level of nesting is another condition the reader must hold in their head. Guard clauses handle the failure cases immediately and exit, so the happy path reads top-to-bottom at zero indentation. Code reviewers at most companies will flag deep nesting — this is the refactor they are asking for.

dedupe.js Arrays & ObjectsBeginner 
const tags = ['css', 'js', 'css', 'html', 'js'];

// A Set can only hold unique values — spread it back out
const unique = [...new Set(tags)];   // ['css', 'js', 'html']

// Bonus: O(1) membership checks vs O(n) for .includes()
const allowedRoles = new Set(['admin', 'editor']);
allowedRoles.has('admin');   // true — instant at any size

Deduplicate with Set

Why pros use it: A Set physically cannot hold duplicates, so spreading one back into an array is the cleanest dedupe there is. The deeper win: set.has() is O(1) while array.includes() scans every element — for repeated membership checks on big lists, the difference is dramatic.

// map + flat in a single pass

Group a list with Object.groupBy

Why pros use it: Grouping used to be the number-one reason to import Lodash. Object.groupBy (Chrome 117+, Firefox 119+, Safari 17.4+) does it natively in one call. Keep the reduce fallback in your toolkit for older targets — and note the tidy ??= operator that creates each bucket on first use.

reduce.js Arrays & ObjectsIntermediate 
const orders = [
  { id: 'a1', total: 40 },
  { id: 'b2', total: 25 },
  { id: 'c3', total: 60 }
];

// Index by id → O(1) lookups instead of .find() everywhere
const byId = orders.reduce((acc, order) => {
  acc[order.id] = order;
  return acc;
}, {});

byId['b2'];   // { id: 'b2', total: 25 } — instantly

// Aggregate in the same shape
const revenue = orders.reduce((sum, o) => sum + o.total, 0);

reduce: shape data, don’t just sum it

Why pros use it: The pattern to internalise is indexing by id: turn an array into a lookup object once, then every subsequent access is O(1) instead of an O(n) .find(). On a list you query hundreds of times — rows by id, users by email — this is one of the highest-value micro-optimisations there is, and it makes the code clearer too.

all-settled.js Async PatternsIntermediate 
const results = await Promise.allSettled([
  fetch('/api/user'),
  fetch('/api/posts'),
  fetch('/api/flaky-service')
]);

results.forEach(result => {
  if (result.status === 'fulfilled') {
    render(result.value);
  } else {

  }

// Promise.all would have rejected everything here

Promise.allSettled: no all-or-nothing

Why pros use it: Promise.all rejects the moment one promise fails — the other results are thrown away. That is right for dependent data, but wrong for dashboards, widget grids and batch jobs where partial success is useful. allSettled always resolves, handing you every outcome to handle individually.

fetch-timeout.js Async PatternsPro 
async function fetchWithTimeout(url, ms = 5000) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), ms);

  try {
    const response = await fetch(url, {
      signal: controller.signal
    });
    return await response.json();
  } finally {
    clearTimeout(timer);
  }
}

// Same primitive, different job: cancel the PREVIOUS
// search when the user types again — no stale results

Fetch with a timeout via AbortController

Why pros use it: fetch has no timeout by default — a hung server can leave your UI spinning forever. AbortController is the platform's cancellation primitive: the same pattern also cancels stale requests in type-ahead search, so a slow response for “ca” can never overwrite results for “cats”.

parallel-await.js Async PatternsIntermediate 
// ❌ Sequential — each await blocks the next (≈600ms)
const user  = await fetchUser();    // 200ms
const posts = await fetchPosts();   // 200ms
const tags  = await fetchTags();    // 200ms

// ✅ Parallel — all three start immediately (≈200ms)

  fetchUser(),
  fetchPosts(),
  fetchTags()
]);

// Rule: if B doesn't need A's result, don't await A first

Parallel await beats sequential await

Why pros use it: Three sequential awaits on 200ms requests take 600ms; in parallel they take 200ms. This is the most common real-world async performance bug — the awaits look identical, but the sequential version quietly serialises independent work. // Wrap any promise into [value, error] — never throws
const attempt = promise =>
  promise
    .then(value => [value, null])
    .catch(error => [null, error]);

const [user, error] = await attempt(fetchUser());

if (error) {
  showToast('Could not load your profile');

  render(user);
}
// Flat, explicit, impossible to forget the error case

Go-style [value, error] tuples

Why pros use it: try/catch around every await pushes the happy path into nested blocks and makes it easy to forget error handling entirely. Wrapping once turns every async call into a flat, explicit two-value check — you can see at the call site that the error case was considered. Popularised by Go, now common in production JS codebases.

storage.js DOM & BrowserBeginner 
const storage = {
  get(key, fallback = null) {
    try {
      const raw = localStorage.getItem(key);
      return raw === null ? fallback : JSON.parse(raw);
    } catch {
      return fallback;   // corrupt JSON or blocked storage
    }
  },
  set(key, value) {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch { /* quota full / private mode — stay calm */ }
  }
};

storage.set('prefs', { theme: 'dark', fontSize: 18 });
storage.get('prefs', {});   // a real object, not a string

A safe localStorage wrapper

Why pros use it: Raw localStorage has three traps: it only stores strings (objects become "[object Object]"), getItem returns null that then crashes JSON.parse chains, and in some private-browsing modes setItem throws. Ten lines of wrapper remove all three permanently.

debounce.js PerformanceIntermediate 
function debounce(fn, delay = 300) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

// 5 keystrokes → ONE request, 300ms after typing stops
const search = debounce(query => {
  fetch('/api/search?q=' + encodeURIComponent(query));
}, 300);

input.addEventListener('input', e => search(e.target.value));

Debounce: wait until they stop

Why pros use it: Typing “hello” fires five input events; without debouncing that is five API calls, four of them wasted. Debounce collapses the burst into one call after the user pauses. The trade-off is latency — results arrive delay ms after the last keystroke — so tune it: ~300ms for search, ~500ms for autosave.

raf-throttle.js PerformancePro 
function rafThrottle(fn) {
  let scheduled = false;
  return (...args) => {
    if (scheduled) return;
    scheduled = true;
    requestAnimationFrame(() => {
      fn(...args);
      scheduled = false;
    });
  };
}

// Runs at most once per frame — never wasted work
window.addEventListener('scroll',
  rafThrottle(() => updateReadingProgress()),
  { passive: true });

Throttle to the frame rate with rAF

Why pros use it: Scroll and pointer events can fire far more often than the screen repaints — any work beyond once per frame is thrown away, yet still burns CPU. requestAnimationFrame throttling runs your handler at most once per paint, perfectly synced to the display. Prefer this over setTimeout throttles for anything visual.

memoize.js PerformancePro 
function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const key = JSON.stringify(args);
    if (!cache.has(key)) {
      cache.set(key, fn(...args));
    }
    return cache.get(key);
  };
}

// Only PURE functions qualify:
// same input → same output, no side effects
const layout = memoize(computeExpensiveLayout);

Memoization: never compute twice

Why pros use it: If a function is pure — same input, same output — recomputing it is pure waste. A Map cache trades memory for speed. Press Run: naive fib(20) makes ~22,000 calls; memoised, 21. The same idea powers React's useMemo and every build-tool cache you have ever waited for.

time-ago.js Utilities & IntlIntermediate 
const rtf = new Intl.RelativeTimeFormat('en', {
  numeric: 'auto'
});

rtf.format(-1, 'day');    // 'yesterday'
rtf.format(-3, 'hour');   // '3 hours ago'
rtf.format(2, 'week');    // 'in 2 weeks'

// Pick the right unit automatically
function timeAgo(date) {
  const s = (date - Date.now()) / 1000;
  const units = [['year', 31536000], ['month', 2592000],
    ['day', 86400], ['hour', 3600], ['minute', 60]];
  for (const [unit, size] of units) {
    if (Math.abs(s) >= size)
      return rtf.format(Math.round(s / size), unit);
  }
  return 'just now';
}

“3 hours ago” with Intl.RelativeTimeFormat

Why pros use it: Relative timestamps were the last big reason teams kept Moment.js (and its 70KB) around. Intl.RelativeTimeFormat handles the grammar — including special forms like “yesterday” via numeric: 'auto' — in every locale, natively. The timeAgo helper below picks the sensible unit for any date.

// Cryptographically strong, collision-safe, built in
const id = crypto.randomUUID();
// '36b8f84d-df4e-4d49-b662-bcde71a8764f'

// ❌ The old hack — collisions are a real risk:

Real unique IDs with crypto.randomUUID

Why pros use it: Math.random() is not collision-safe — with enough generated IDs, duplicates will happen, and the resulting bugs (two list rows sharing a key, overwritten records) are miserable to trace. crypto.randomUUID() produces cryptographically strong v4 UUIDs natively. proxy-state.js Modern SyntaxPro 
function reactive(target, onChange) {
  return new Proxy(target, {
    set(obj, key, value) {
      const old = obj[key];
      obj[key] = value;
      if (old !== value) onChange(key, value);
      return true;   // signal success (strict mode cares)
    }
  });
}

const state = reactive({ count: 0 }, (key, value) => {
  render(`${key} changed to ${value}`);
});

state.count = 1;   // render() fires automatically
state.count = 2;   // and again — no framework involved

Proxy: reactive state in 15 lines

Why pros use it: A Proxy intercepts property access on an object — which is exactly how Vue's reactivity and many state libraries work under the hood. The set trap fires on every assignment, so "change state, UI updates itself" needs no framework at all. The trade-off: proxies intercept the wrapper, so state.user.name = x on nested objects needs recursive wrapping — which is precisely what reactivity libraries sell you.

generators.js Modern SyntaxPro 
function* fibonacci() {
  let [a, b] = [0, 1];
  while (true) {          // infinite — and totally safe
    yield a;
    [a, b] = [b, a + b];
  }
}

// take(n): consume just n values from any generator
function take(gen, n) {
  const out = [];
  for (const value of gen) {
    out.push(value);
    if (out.length === n) break;
  }
  return out;
}

take(fibonacci(), 8);   // [0, 1, 1, 2, 3, 5, 8, 13]

Generators: lazy, even infinite, sequences

Why pros use it: A generator produces values on demand — it pauses at every yield until someone asks for the next value. That makes "infinite" sequences safe: nothing is computed until consumed. Pros reach for them for ID factories, pagination cursors, and processing huge datasets without building huge arrays. function* looks alien for a week, then becomes a superpower.

pipe.js Utilities & IntlIntermediate

  (input) => fns.reduce((value, fn) => fn(value), input);

// Small, single-purpose, individually testable steps
const trim      = s => s.trim();

Why “modern” JavaScript matters

Most of the snippets on this page replace patterns that needed a utility library five years ago. Deep cloning used to mean importing Lodash; formatting a date meant Moment.js; generating an ID meant a UUID package. Today structuredClone, Intl and crypto.randomUUID are built into every modern browser — shipping a library to do the same work just adds bundle weight, slows your page and widens your dependency attack surface.

Knowing what the platform now does natively is one of the clearest markers separating junior from senior frontend work. The platform team at every browser vendor has spent a decade absorbing the best ideas from userland libraries — the modern developer's job is to know they landed.

Copy less, understand more

Every snippet here is deliberately short enough to read in one sitting, and each one names the trade-off it makes. A debounce delays work at the cost of latency; event delegation saves memory at the cost of one extra DOM lookup per click; Promise.all is fast but fails as a group. Understanding the trade-off is what lets you decide when not to use a pattern — which is the skill interviews actually probe for.

All code on this page is dependency-free, framework-agnostic and safe to paste into any project — vanilla JS, React, Vue or Svelte alike. No attribution needed.

Each one had to clear three bars: it must replace a pattern that is either longer, more error-prone or more dependency-heavy; it must work in every modern browser without a transpiler; and the explanation must fit in a paragraph. New snippets are added as the JavaScript platform evolves — when a proposal moves to Stage 4 and browsers ship it, the collection grows. Object.groupBy, Array.fromAsync and the using keyword for resource disposal are the most recent additions. Patterns that become so mainstream they stop needing explanation are retired to keep the collection useful rather than encyclopaedic.

Frequently asked questions

Can I use these JavaScript snippets in my own projects?

Yes — every snippet is free for personal and commercial use with no attribution. They're all dependency-free vanilla JavaScript, so they paste cleanly into any project, framework or build setup.

Which browsers do these modern JavaScript features support?

Everything on the page works in current Chrome, Edge, Firefox and Safari. Where a feature is newer — like Object.groupBy — the snippet says so and includes a fallback for older targets.

Why vanilla JavaScript instead of a framework or Lodash?

Because the platform caught up: structuredClone, Intl, crypto.randomUUID and friends now do natively what once needed libraries. Knowing the built-ins means smaller bundles, fewer dependencies to audit, and skills that transfer to every codebase.
